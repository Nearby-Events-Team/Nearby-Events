Local Event Bulletin Board

Any event info, in any format, becomes a structured, trusted, discoverable event in seconds.

Cognizant GCP Hackathon, Use Case 5. Build window 2 to 5 Oct 2026. Evaluation 6 Oct 2026.

1. Why Use Case 5

Use cases 1, 3, 4 and 5 are all basic CRUD with SQLite, so most teams will submit near-identical apps. The panel scores architecture, alternatives considered, real-time capability, monitoring, UX and presentation. Those are where we win.

2. Core features (required, must be flawless)

  • Card grid with the next upcoming event first
  • Post form: title, date/time, location, description
  • Date-sorted query
  • Expiry: hide past events in the query and clean up on a schedule
  • "I'm Going" counter, one RSVP per device, rate limited
  • Color-coded category badges
  • Neighborhood search
  • Shareable links with a unique event ID

Alternatives considered

  • VM + SQLite is simple but needs manual scaling, patching and polling for live updates.
  • Cloud SQL handles the sorted query fine but adds cost and lacks built-in real-time listeners.
  • Cloud Run + Firestore (chosen) gives serverless scaling, live updates, TTL expiry and a one-command deploy.
